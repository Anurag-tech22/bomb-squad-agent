# Security & Zero-Trust Policy

The Autonomous DevOps Bomb Squad project treats safety and zero-trust execution as primary architectural invariants.

---

## 🛡️ Threat Model & Safety Invariants

1. **Isolation Boundary:**
   Untrusted remediation code generated by reasoning LLMs must only execute within isolated Daytona Cloud Sandboxes with network egress disabled.
2. **State Mutation Gates:**
   Any operation capable of data loss or service disruption (cache eviction, server restart, config change) requires deterministic Human-in-the-Loop (HITL) approval with the `TF-007-EVIC-REQ` verification token.
3. **Secret Hygiene:**
   Never commit API keys or production credentials to git. All credentials must be sourced from environment variables (`.env`).

---

## 🚨 Reporting a Vulnerability

If you discover a security vulnerability or safety bypass in the agent runtime:
1. Please open a private security advisory on GitHub or contact the maintainers at `anuragthopate2005@gmail.com`.
2. Do not disclose security vulnerabilities publicly until a patch is released.
